## 體檢的 5 個面向

請按以下面向逐一檢查，**每個面向產出獨立章節**。

### 1. 正確性問題

- 邊界條件處理：空集合、null、長字串、極端數值
- 異常處理：是否有 `catch (Exception e) {}` 吃掉異常的地方
- 執行緒安全：ThreadLocal 是否在請求結束時清理、靜態變數是否被多執行緒修改
- 交易邊界：`@Transactional` 是否用對地方、是否有跨方法的交易陷阱
- Redis 與 MySQL 一致性：哪些地方可能出現「Redis 寫成功 DB 寫失敗」

### 2. 效能問題

- N+1 查詢：MyBatis Mapper 是否有循環內查詢
- 無限制查詢：是否有 `SELECT * FROM` 沒有 LIMIT 的地方
- 無用快取或快取失效策略不當
- Redis 操作是否未 pipeline / 是否有 KEYS 之類災難級操作
- 大物件序列化進 Redis

### 3. 安全問題

- SQL 注入風險（特別是字串拼接 SQL 的地方）
- JWT 漏洞：密鑰是否硬編碼、過期時間是否合理、是否驗簽
- 密碼處理：是否明文儲存、是否用 BCrypt
- CORS 配置：是否過於寬鬆（`*`）
- 敏感資訊洩漏：log 是否印出密碼/token、API 是否回傳過多內部欄位

### 4. 架構問題

- 循環依賴：Service A → B → A
- 職責不清：Controller 裡寫業務邏輯、Service 裡寫 SQL
- 過大類別：超過 500 行的類別
- 重複代碼：多個 Service 有相同邏輯但沒抽出
- 命名問題：類別/方法名不清楚或誤導

### 5. Spring Boot 2.7 → 3.x 升級會壞掉的地方

> 這一節**特別重要**，因為這個專案接下來會升級到 Spring Boot 3.x + Java 21。

- `javax.*` → `jakarta.*` 需要改的所有 import
- Spring Security 舊配置（`WebSecurityConfigurerAdapter` 等）
- 已棄用的 API：找出所有 `@Deprecated` 或 Spring Boot 3 已移除的 API
- MyBatis-Plus / Mybatis 版本相容性問題（但本專案會改成 JPA，這部分可以記錄但不用深究）
- Jackson / Lombok 等套件版本相容性

## 規則

1. **不要動任何代碼**，只產出報告
2. **每個問題都要附上具體檔案路徑和行號**，方便我後續驗證
3. **不要編造問題**——如果某個面向沒找到問題，直接寫「未發現明顯問題」，不要為了湊數而硬找
4. **嚴重等級分類標準**：
   - 高：會造成資料錯誤、安全漏洞、線上事故
   - 中：影響效能、可維護性，但短期內不致命
   - 低：風格、命名、可讀性問題
5. **體檢完成後，不要主動進入下一階段**——等我看完報告，決定哪些先修
